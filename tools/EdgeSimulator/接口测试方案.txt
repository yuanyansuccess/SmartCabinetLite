边缘计算机模拟器 — 接口测试方案
====================================
依据：《智能工具柜配置项通信协议》（M0冻结版）
工具：EdgeSimulator.exe（本目录，--auto-connect 可一键连接）
原则：每个按钮=一个协议接口/场景；上位机侧验证看其日志
      （QtSmartCabinet.exe 同级 logs\app_日期.log）。

════════════════════════════════════════
一、周期帧接口（协议3.4）
════════════════════════════════════════
TC-01  周期帧自动发送
  操作：连接后默认开启，每3秒一帧（间隔可改）
  期望：上位机日志持续"收到周期帧"；界面状态在线
TC-02  立即发一帧
  操作：点【立即发一帧周期帧】
  期望：上位机日志出现一帧 periodic
TC-03  CAM1/CAM2 自检5态
  操作：下拉分别选 ok/offline/low_light/dirty/comm_error，点【立即发一帧】
  期望：上位机 camera_status 解析出对应状态（具体以硬件选型为准）
TC-04  uptime_sec
  操作：改 uptime 数值后发送
  期望：上位机日志"运行 N 秒"与所设一致
TC-04B 空 camera_status（3.4 自检缺席容错）
  操作：两个相机下拉都选"(空-不报自检)"，点【立即发一帧】
  期望：camera_status 为空数组[]，上位机解析不崩、界面无相机异常提示
TC-04C 单相机缺席
  操作：CAM2 选"(空-不报自检)"，发送
  期望：camera_status 只含 CAM1 一条
TC-05  停发周期帧→离线判定（第5章/第6章）
  操作：点【停发周期帧】或取消"自动发送"勾选
  期望：15秒后上位机日志"边缘机链路离线"；恢复发送后"链路在线"
      并自动补发离线期间的未回应请求（原request_id）

════════════════════════════════════════
二、识别回应接口（协议3.3）
════════════════════════════════════════
前置：上位机建出入库单并点确认，关柜后发起一次 recognize_req
TC-06  正常清单
  操作：点【正常清单（2条样例）】
  期望：上位机 recognizeFinished，items=2，request_id 配对
TC-07  有借有还（3.3-①）
  操作：点【有借有还】
  期望：清单 2 条，A-01-05 以 tool_id 为空回报（该货位工具已取走，空货位不省略）、
      A-01-06 带套筒编号（归还新位）；上位机按货位比对并更新台账
TC-08  无变化·空清单（3.3-②）
  操作：点【无变化·空清单】
  期望：结构层按合法帧放行（items 为空数组）；本机组有在库货位时上位机会判
        "识别清单为空、未回报库内在库货位"，弹核对失败并落识别故障告警，本次不写库。
        只有本机组没有已登记货位时才会按无变化直接结束。
TC-09  错放告警（3.3-③）
  操作：点【错放告警】
  期望：上位机按 alert_type=misplaced 提示应放位置
TC-10  未知物告警
  操作：点【未知物告警】
  期望：上位机按 alert_type=unknown 提示人工确认
TC-11  置信度不足告警
  操作：点【置信度不足告警】
  期望：上位机提示"识别不确定"，该条不写入台账
TC-12  延迟回应（测超时边界）
  操作：设延迟4000ms（>3秒），点【延迟回应】
  期望：上位机3秒超时重发（原request_id），最终收到迟到回应
TC-13  重复回应×2（测去重，3.6-③）
  操作：点【重复回应×2】
  期望：上位机只入账一次，第二次被丢弃并计数
TC-14  两帧拼一行（测粘包分帧，第2章）
  操作：点【两帧拼一行】
  期望：上位机按行拆出两帧，链路正常
TC-15  不回应（测超时重发，第5章）
  操作：点【不回应】关闭自动回应，触发上位机发请求
  期望：上位机3秒×2重发（共3次发送），9秒后记失败并保留请求
TC-16  乱序request_id（3.6-②）
  操作：点【回应乱序request_id】
  期望：上位机丢弃并计数，不影响后续正常请求
TC-16B missing告警（3.3字段枚举边界）
  操作：点【缺失告警：missing，测字段枚举边界】
  期望：上位机正确解析 alert_type=missing（协议枚举 5 个值
        none/misplaced/unknown/missing/low_confidence 均已覆盖）

三、软件版本（随周期帧上报）
════════════════════════════════════════
TC-17  周期帧带版本号
  操作：连接后看周期帧自动上报
  期望：周期帧带 software_version 字段，上位机显示软件版本
TC-18  版本字段核对
  操作：对照周期帧里的 software_version 与上位机界面显示
  期望：两处一致；不再有单独的版本查询与回应帧

四、通信异常接口（协议3.6）
════════════════════════════════════════
TC-19  非法JSON帧（3.6-②）
  操作：点【注入非法JSON帧】
  期望：上位机丢弃计数、日志记坏帧、链路不断
TC-20  未知type帧（3.6-②）
  操作：点【注入未知type帧】
  期望：同上，丢弃计数
TC-21  超长帧>1MB（断开保护）
  操作：点【注入超长帧】
  期望：上位机断开该连接并告警，程序不崩
TC-22  断开连接（断链）
  操作：点【断开连接】
  期望：上位机立即判离线；重连后恢复正常
TC-22B 自动重连（模拟真实边缘机退避重连）
  操作：保持"断开后自动重连"勾选，杀掉上位机进程再重启，
        或拔插网线
  期望：模拟器按 1/2/4/8/16/30 秒退避自动重连，日志记录每次退避；
        重连成功后周期帧恢复、上位机重新判在线并补发未回应请求
        （取消勾选=手动模式，断开后不重连，需点【连接】）

  ────────────────────────────────────────
  TC-24 系列：识别清单结构校验（协议3.3）
  ────────────────────────────────────────
  统一验收：结构不合规的帧必须让上位机弹【核对失败】并写明原因，工具台账与借用记录不变；
            空清单、缺 alert_type、以及多带协议外历史字段属合法或兼容帧，不得被判成结构错误。
  协议3.3 的 items 每项 4 个字段：position / tool_id（无工具时为空） / confidence(0~1) /
      alert_type(none|misplaced|unknown|missing|low_confidence)。
  回报范围 = 本机组全部已登记货位：tool_position_mapping 中 in_stock/pending/checked_out/
      borrowed 四种状态各一条，一项一货位不得重复；在库货位 tool_id 为真实编号，
      其余状态 tool_id 置空但行不得省略。库里没有货位定义表，从未登记过的物理空位取不到。
  结构错场景与内置场景是故意违规帧或协议样例帧，不读库、不受全量清单口径约束。
  操作口径：③页「回应场景」下拉选一项 → 上位机建单点确认，模拟器自动回对应帧；
            ④页下拉选同一项后点【立即注入一帧】，可在请求已发出时立刻补测，不必重新建单。
            TC-24-14/15 无固定下拉场景，用「自定义帧」页按用例描述手改帧后发送（见 TC-23E、TC-26-05）。

TC-24-01  缺 items 字段
  期望：弹【核对失败】，写明"识别清单结构不符合协议"，本次零写库
TC-24-02  items 是对象非数组
  期望：同上
TC-24-03  item 缺 position
  期望：同上
TC-24-04  position 是数字（类型错）
  期望：同上
TC-24-05  缺 request_id
  期望：上位机丢弃计数，约9秒后弹"识别请求超时"；不配对的帧不进业务，本次零写库
TC-24-06  type 未知
  期望：同上丢弃计数、约9秒超时
TC-24-07  item 缺 tool_id（最危险）
  期望：弹【核对失败】并写明原因，本次零写库；工具未取走不得被记成已出库
TC-24-08  tool_id 是数字
  期望：弹【核对失败】并写明原因，本次零写库
TC-24-09  缺 confidence
  期望：同上
TC-24-10  confidence 是字符串
  期望：同上
TC-24-11  confidence=99 超出 0~1
  期望：同上
TC-24-12  缺 alert_type
  期望：上位机按无告警兼容处理，正常核对通过，不判失败
TC-24-13  alert_type 不在协议枚举内
  期望：弹【核对失败】并写明原因，本次零写库
TC-24-14  帧里多带协议外历史字段（如 present）
  期望：上位机忽略该字段，正常核对通过，不判失败（向后兼容未升级的边缘机）
TC-24-15  空货位：tool_id 为空且该货位仍在清单中
  期望：出库判取出正确、全柜核对判该货位已空
TC-24-16  同一货位重复上报两条
  期望：弹【核对失败】并写明原因，本次零写库
TC-24-17  items 里的元素是字符串而非对象
  期望：同上

════════════════════════════════════════
五、自定义帧（协议外调试/自建异常扩展入口）
════════════════════════════════════════
TC-23  任意JSON
  操作：自定义页签写任意一行JSON，点【发送（编辑框所见即所发）】
  期望：按协议分帧规则送达；JSON格式错误本地提示
TC-23B 原文发送（坏帧/任意字节）
  操作：勾选"原文发送"，写任意文本（如"坏帧测试xxx"），点【发送】
  期望：原样送达，上位机丢弃计数不断链（3.6-②）
TC-23C 多帧粘包组合
  操作：编辑框写两行JSON（不勾选原文），点【发送】
  期望：两帧逐条校验后发出，上位机分别处理
TC-23D 循环发送（压力测试）
  操作：编辑框写好内容，设间隔3000ms，点【启动循环发送】
  期望：按间隔持续发送，日志可见；点【停止循环发送】结束
TC-23E 协议外字段容错
  操作：发带额外字段的ack：{"type":"recognize_ack","request_id":"r-x","items":[],"extra":1}
  期望：上位机忽略未知字段，正常处理（协议未定义的字段不影响解析）

  ────────────────────────────────────────
  TC-26 系列：自己改帧发出去（不依赖预制场景）
  ────────────────────────────────────────
  统一口径：②页「发送帧 JSON」编辑框里的内容就是最终发出的 recognize_ack 帧；
            清单表、预制场景、结构错下拉都只是"载入起点"，载入后照样能改字段、改取值、改缩进。

TC-26-01  占位符自动回带编号
  操作：②页帧 JSON 编辑框写 {"type":"recognize_ack","request_id":"{{request_id}}","items":[...]}，
        上位机发起一次识别核对（自动回应即按此帧发）
  期望：日志里 TX 帧的 request_id 是本次上位机下发的真实编号；上位机不再按"编号认不出"丢弃
TC-26-02  没有在途请求时保留占位符
  操作：把帧 copy 到④页自定义帧编辑框，不发起核对直接点【发送】
  期望：日志提示"占位符未替换、这帧会被丢弃"；帧里仍是 {{request_id}}
TC-26-03  多行缩进 JSON 自由改格式
  操作：点【整理排版】或手工把一帧写成带换行缩进的多行 JSON，改一个字段值后点【发送】
  期望：整段当成一帧发出，上位机收到的是改后的值；不会按行拆成多条解析失败
TC-26-04  从③页场景载入后再改
  操作：③页选任一【结构错】场景 → ④页点【载入③页当前场景帧】→ 在编辑框里增删字段 → 发送
  期望：发出的是编辑框里改过的内容，不是预制场景原帧
TC-26-05  在②页帧 JSON 里直接改结构
  操作：②页生成清单后，在【发送帧 JSON】编辑框里删掉某行的 tool_id 或把它改成数字，
        上位机发起一次识别核对（自动回应）；也可把帧送到④页手动点【发送】
  期望：帧按改动后的内容发出；坏结构时上位机弹核对失败、零写库
TC-26-06  原有能力不回退
  操作：编辑框写两行各一帧测逐行；③页点【两帧拼一行】测粘包；勾选【原文发送】发坏帧文本；启动循环发送
  期望：四种原有用法都不受"整段优先"影响，逐行/粘包/原文/循环行为与之前一致
TC-26-07  手改后表格不覆盖、显式重新生成才覆盖
  操作：在帧 JSON 里删一个字段 → 改上面表格某个单元格 → 看帧 JSON 是否保持手改内容 →
        点【从表格重新生成帧】
  期望：表格变化不覆盖手改帧；点重新生成后帧按表格内容恢复，统计与状态提示同步
TC-26-08  告警类型下拉对齐上位机枚举
  操作：②页任一行的"告警类型"下拉逐项选 5 个值 → 点【从表格重新生成帧】→ 看帧 JSON 的
        alert_type → 上位机发起核对
  期望：下拉只有 none/misplaced/unknown/missing/low_confidence 五项；帧里逐字一致；
        五个值上位机都接受，只有枚举外值才弹核对失败、零写库
TC-26-09  本机组全部已登记货位清单（含空货位）
  操作：①页选好机组 → 顶部点【一键标准联调】或②页点【按本单生成清单】
        → 看【发送帧 JSON】编辑框 → 上位机建单点确认
  期望：items 覆盖该机组 tool_position_mapping 里 in_stock/pending/checked_out/borrowed
        全部已登记货位，一项一货位不重复；在库货位 tool_id 为真实编号，其余货位
        tool_id 为空但这一行仍在清单里；上位机 recognizeFinished 正常放行、不弹核对失败；
        会话页按货位覆盖检查通过，不误判"位置反馈不全"。
  说明：库里没有货位定义表，从未登记过的物理空位取不到。
TC-26-10  立即回一条开柜成功 open_ack
  操作：上位机点一次开柜后，③页点【回开柜成功】
  期望：模拟器日志出现"主动发送 open_ack（result=1）"并打印取自最近一次 open_req 的编号；
        帧为 {"type":"open_ack","request_id":"...","result":1,"message":""}；
        上位机 openFinished 判开柜成功（如该编号仍在途）。
TC-26-11  立即回一条开柜失败 open_ack
  操作：上位机点一次开柜后，在"失败原因文案"填原因，③页点【回开柜失败】
  期望：模拟器发 result=0、message 为所填原因；上位机 openFinished 判失败并显示原因。
TC-26-12  主动回应不受回应策略约束 / 重复编号丢弃
  操作：把"回应策略"设成【不回应】，上位机点一次开柜后连点两次【回开柜成功】
  期望：两次都主动发出 open_ack；第一次配对成功，第二次被上位机按重复编号丢弃并计数；
        从未收到过 open_req 时点按钮只提示、不发编号为空的帧。

六、回归组合（建议每次发版前全跑一遍）
════════════════════════════════════════
  ① 连接 → TC-01/02/03 周期帧全态 → TC-04B/04C 空自检容错
  ② TC-06 正常往返 → TC-13 去重 → TC-16/16B 乱序/missing

        确认坏帧零写库、好帧正常通过
  ⑥ TC-17/18 周期帧与版本字段
  ⑦ TC-22B 自动重连（杀上位机进程再重启）
  ⑧ TC-26-08 告警类型下拉 5 个取值逐项发一遍，确认上位机都接受
  ⑨ TC-26-09 本机组全部已登记货位清单（含空货位）→ TC-26-10/11/12 立即回开柜成功/失败
