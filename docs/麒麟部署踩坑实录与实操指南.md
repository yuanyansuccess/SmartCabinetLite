# 智能工具柜系统（SmartCabinetLite）麒麟系统部署踩坑实录与实操指南

> 整理日期：2026-10-20
> 适用版本：Qt 6.5.3 / 麒麟 Kylin x86_64（gcc_64）/ 当前 main 分支
> 目标读者：后续需要在麒麟上重新部署、或排查摄像头/编译问题的同事
> 前提要求：本文所有“改源码”动作都只是为了**让麒麟能编译通过**，编译完成后**必须还原**，源码最终零改动。

---

## 一、最重要的结论（先读这段）

1. **Windows 能出摄像头画面，麒麟黑屏，不是同一个后端**：
   - Windows 构建走 **Media Foundation**（Windows 专属，自带，无需额外模块）。
   - 当前 git 代码的 Linux/麒麟摄像头实现**只有一条路**：写在 `#ifdef HAS_QT_MULTIMEDIA` 宏后面（`CMakeLists.txt` 53–60 行）。
   - 麒麟上摄像头能不能用，**完全取决于 Qt 是否装了 Multimedia 模块**。

2. **本机 `/opt/Qt/6.5.3/gcc_64` 当初没装 Multimedia 模块**，所以 `HAS_QT_MULTIMEDIA` 未定义 → 整段摄像头代码被编译跳过 → 登录页显示的是“无摄像头”占位符（黑圆），不是画面。

3. **“10-19 开发的 V4L2 直采后端”在当前 git 里已经不存在**（无 stash、无历史提交、无其他分支），代码里只有 Qt Multimedia 这一条路。不要再去找 V4L2 代码。

4. **唯一的零代码改动方案**：把缺失的 **Qt6 Multimedia 模块**装进 `/opt/Qt`，重新编译时宏自动打开。其余都是“让它能编过/跑起来”的环境与流程问题。

## 三、推荐部署流程（端到端）

### 步骤 1：安装 Qt6 Multimedia 模块（需 sudo，一次性）

模块包已验证可用，地址要点：**版本号与文件名直接拼接，没有斜杠**（很多人会 404 就栽在这）。

```bash
# 下载（如本地已有 /tmp/qtmultimedia.7z 可跳过）
cd /tmp
curl -L -o /tmp/qtmultimedia.7z \
  "https://download.qt.io/online/qtsdkrepository/linux_x64/desktop/qt6_653/qt.qt6.653.addons.qtmultimedia.gcc_64/6.5.3-0-202309260341qtmultimedia-Linux-RHEL_8_4-GCC-Linux-RHEL_8_4-X86_64.7z"

# 安装（归档内部根目录就是 6.5.3/gcc_64/，直接合并进现有 Qt）
sudo 7z x /tmp/qtmultimedia.7z -o/opt/Qt/

# 确认
ls -l /opt/Qt/6.5.3/gcc_64/lib/libQt6Multimedia.so
ls /opt/Qt/6.5.3/gcc_64/plugins/multimedia/   # 应有 libgstreamermediaplugin.so + libffmpegmediaplugin.so
```

> ⚠️ 模块**必须装进 `/opt/Qt`**：`CMakeLists.txt` 把 Qt 路径**写死成 `/opt/Qt/6.5.3/gcc_64`**（31–43 行），且 Qt6Config 经符号链接会被解析回 `/opt/Qt`，所以“私有 Qt 树/符号链接”方案走不通，必须写进 `/opt/Qt`（需要 sudo）。

### 步骤 2：临时打补丁让源码在麒麟编过（编完还原，见第五节）

需要 3 类补丁才能编过（详见第五节代码片段）：
- 2 个 `.ui` 补 `SearchBar` 的 `customwidget` 声明（大小写敏感问题）。
- 1 个 `.cpp` 给两个 lambda 补 `this` 捕获（`SystemSettingsPageDisplay.cpp`）。
- `CameraCapture.cpp`：用 `#ifndef HAS_QT_MULTIMEDIA` 包住 5 个通用函数（否则与 Multimedia 版重定义），并补 `<QMediaDevices>`/`<QVideoSink>` 头。

### 步骤 3：配置并编译（带注入的编译/链接参数）

模块装好后 CMake 会自动 `add_compile_definitions(HAS_QT_MULTIMEDIA)`，**但 CMakeLists 没有链接 `Qt6::Multimedia`**，需通过变量注入头文件路径、链接库，并放行一个永不调用的未定义符号（见坑 2、坑 3）：

```bash
export PATH="/opt/Qt/6.5.3/gcc_64/bin:$HOME/nodebin/bin:$PATH"
cd /data/usershare/SmartCabinet/SmartCabinetLite
rm -rf build-kylin && mkdir -p build-kylin && cd build-kylin

cmake .. -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=../deploy-kylin -G "Unix Makefiles" \
  -DCMAKE_CXX_FLAGS="-I/opt/Qt/6.5.3/gcc_64/include/QtMultimedia" \
  -DCMAKE_CXX_STANDARD_LIBRARIES="-L/opt/Qt/6.5.3/gcc_64/lib -lQt6Multimedia" \
  -DCMAKE_EXE_LINKER_FLAGS="-Wl,--allow-shlib-undefined"

make -j$(nproc)
make install
```

配置阶段应看到：`-- Linux/Kylin: Qt Multimedia camera enabled`。

### 步骤 4：补齐运行时插件与启动脚本

`deployment/build_kylin.sh` 只复制 `sqldrivers`/`platforms` 插件，**不会复制 multimedia 插件**，需手动补：

```bash
cd /data/usershare/SmartCabinet/SmartCabinetLite
mkdir -p deploy-kylin/plugins/multimedia
cp -r /opt/Qt/6.5.3/gcc_64/plugins/multimedia/. deploy-kylin/plugins/multimedia/

# 人脸服务
cp -r tools/face-recognition/. deploy-kylin/bin/tools/face-recognition/
# system.ini
cp build/system.ini deploy-kylin/bin/system.ini

# start.sh（Qt lib 路径 + 插件路径必须正确）
cat > deploy-kylin/start.sh <<'EOF'
#!/bin/bash
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
export LD_LIBRARY_PATH="/opt/Qt/6.5.3/gcc_64/lib:${SCRIPT_DIR}/lib:${LD_LIBRARY_PATH}"
export QT_PLUGIN_PATH="${SCRIPT_DIR}/plugins:${QT_PLUGIN_PATH}"
export QT_QPA_PLATFORM_PLUGIN_PATH="${SCRIPT_DIR}/plugins/platforms"
"${SCRIPT_DIR}/bin/QtSmartCabinet" "$@"
EOF
chmod +x deploy-kylin/start.sh
```

### 步骤 5：让程序使用正确的摄像头（video2 而非 video0）

程序**没有选摄像头的设置项**，默认用枚举列表第一个 = `video0`（内置暗摄像头）。隐藏内置摄像头即可让 Qt 落到 `video2`：

```bash
sudo chmod 000 /dev/video0 /dev/video1      # 隐藏内置摄像头
# 恢复：sudo chmod 660 /dev/video0 /dev/video1
```

重启后也想要此效果（可选），写一条 udev 规则：
```bash
echo 'ACTION=="add", KERNEL=="video[01]", MODE="000"' | sudo tee /etc/udev/rules.d/99-hide-internal-cam.rules
```

### 步骤 6：运行与冒烟验证

```bash
cd /data/usershare/SmartCabinet/SmartCabinetLite
./deploy-kylin/start.sh
```

无界面自检（SSH/远程排障时用）：
```bash
QT_QPA_PLATFORM=offscreen ./deploy-kylin/start.sh > /tmp/app.log 2>&1 &
sleep 15
grep -iE "Qt Multimedia camera started|MySQL connected via \"QMYSQL\"|人脸识别服务就绪" /tmp/app.log
curl -s http://127.0.0.1:8089/health ; echo   # 期望 {"ready":true,"modelsLoaded":true}
# 清理
kill %1; pkill -f "face-server.js"   # 注意：宽模式 pkill 可能被安全策略拦截，用 pgrep+kill 具体 PID
```

## 四、踩坑实录（按“卡住时长”排序）

### 坑 1：三个跨平台编译错误（Windows 能编，麒麟编不过）
- **现象**：`fatal error: searchbar.h: 没有那个文件或目录`；或 lambda `‘this’ was not captured`。
- **根因**：
  1. `UserManagementPage.ui` / `AlertLogsPage.ui` 用了 `SearchBar` 控件却**没在 `<customwidgets>` 声明**，uic 按类名小写生成 `#include <searchbar.h>`；Linux 大小写敏感 → 找不到 `SearchBar.h`。
  2. `SystemSettingsPageDisplay.cpp` 两个 lambda（约 108、235 行）调用 `sender()` 却**没捕获 `this`**，Linux 严格检查直接报错。
- **处理**：临时补丁，编译完还原（代码片段见第五节）。**这是仓库潜藏的“麒麟无法开箱编译” bug，应作为缺陷报给开发。**

### 坑 2：CMakeLists 定义了 `HAS_QT_MULTIMEDIA` 却从不链接库
- **现象**：`CameraCapture.h:29: fatal error: QCamera: 没有那个文件或目录`，随后 `undefined reference to QCamera::staticMetaObject`。
- **根因**：53–60 行只 `add_compile_definitions(HAS_QT_MULTIMEDIA)`，目标**既不添加 Multimedia 头文件路径、也不链接 `Qt6::Multimedia`**。这条麒麟摄像头路径在仓库里本身就是残缺的。
- **处理**：通过 `-DCMAKE_CXX_FLAGS`（头文件路径）+ `-DCMAKE_CXX_STANDARD_LIBRARIES`（库，必须出现在链接行末尾）注入，见步骤 3。

### 坑 3：/opt/Qt 的 libQt6Gui 无 Vulkan，Multimedia 模块却引用它
- **现象**：`libQt6Multimedia.so: undefined reference to QWindow::vulkanInstance() const@Qt_6`。
- **根因**：本机 `/opt/Qt` 的 `libQt6Gui.so.6.5.3` 是 **无 Vulkan 构建**（`readelf --dyn-syms` 确认无 `vulkanInstance` 符号）。官方 Multimedia 模块（RHEL_8_4 构建）引用了它。本程序**从不使用 Vulkan**，可安全放行。
- **处理**：`-DCMAKE_EXE_LINKER_FLAGS="-Wl,--allow-shlib-undefined"`。运行期只要不真正调用 `vulkanInstance()`（Qt Multimedia+GStreamer 取摄像头不会调用），程序正常。

### 坑 4：模块必须装进 /opt/Qt（私有树/符号链接方案失败）
- **现象**：用私有 Qt 树 + `-DCMAKE_PREFIX_PATH` 时，CMake 仍报 `Qt6 found: /opt/Qt/...` 且 `Qt Multimedia not found`。
- **根因**：CMakeLists 写死 `QT_SEARCH_PATHS "/opt/Qt/6.5.3/gcc_64"` 并 `set(CMAKE_PREFIX_PATH)`，覆盖外部传入；且 Qt6Config.cmake 一旦是符号链接，CMake 会解析回真实路径 `/opt/Qt`，导致组件搜索仍回到 `/opt/Qt` 找不到模块。
- **处理**：直接用 `sudo 7z x ... -o/opt/Qt/` 装进写死路径。

### 坑 5：编译脚本不复制 multimedia 插件
- **现象**：程序能启动，但取不到摄像头（缺 GStreamer 后端插件）。
- **根因**：`build_kylin.sh` 只 `cp` `sqldrivers`/`platforms`，没有 `multimedia`。
- **处理**：手动 `cp -r /opt/Qt/.../plugins/multimedia/. deploy-kylin/plugins/multimedia/`，`start.sh` 的 `QT_PLUGIN_PATH` 已指向 `deploy-kylin/plugins`。

### 坑 6：摄像头选错设备（video0 而非 video2）
- **现象**：程序“有摄像头了”但画面是黑的（其实是拍的内置暗摄像头）。
- **根因**：程序无摄像头选择 UI，默认枚举第一项 `/dev/video0`。
- **处理**：`sudo chmod 000 /dev/video0 /dev/video1` 隐藏内置摄像头（见步骤 5）。可用 `ffmpeg -f v4l2 -i /dev/video2 -frames:v 1 out.jpg` 提前确认 video2 能出图。

### 坑 7：检查点面板“撤销”会冲掉临时补丁
- **现象**：编译中途“老错误”复发（`searchbar.h`、`sender()` 又出现）。
- **根因**：在 IDE 检查点面板点“撤销/保留”，会把**尚未还原的 AI 临时编辑**一起回滚（本次就发生过一次，导致 `.ui`/`.cpp` 补丁丢失，而稍后的 `CameraCapture.cpp` 补丁因时间点靠后保留）。
- **处理**：**编译/部署进行中，不要碰检查点面板的“撤销/保留”**。所有临时补丁在流程结束时会用 `git checkout` 主动还原，源码最终应干净。判断源码是否干净：
  ```bash
  git status --short -- src/    # 输出为空即干净
  ```

### 坑 8：主页菜单图标显示为“X 豆腐块”（Windows 正常，麒麟缺 emoji 字体）
- **现象**：主页菜单卡片里 人员管理/工具管理/导入导出/系统告警/操作告警 的图标显示为叉号方框；只有 工具出入库(📦)/系统设置(⚙️) 正常。Windows 下全部正常。
- **根因**：图标是 emoji 字符（`MainWindow.cpp` 菜单定义：👥🔧📦📂🚨📝⚙️），Windows 靠自带 Segoe UI Emoji 渲染；麒麟系统 **emoji 字体数为 0**，无字体覆盖的码点就渲染成豆腐块。📦/⚙️ 正常只是因为 `NotoSansSymbols2`/`DejaVu` 碰巧覆盖了这几个码点。
- **诊断方法**：
  ```bash
  fc-list | grep -icE "emoji"                       # 0 = 无 emoji 字体
  fc-list ":charset=1F465" family                   # 查具体码点（👥）有无字体覆盖
  ```
- **处理（零代码、零 sudo）**：装用户级 emoji 字体。注意 jsdelivr/GitHub raw 对该仓库会返回 4KB 错误页（LFS 问题），用 Debian 镜像的 deb 解包最稳：
  ```bash
  mkdir -p ~/.local/share/fonts && cd /tmp
  DEB=$(curl -s "http://mirrors.ustc.edu.cn/debian/pool/main/f/fonts-noto-color-emoji/" \
        | grep -oE 'fonts-noto-color-emoji_[0-9][^"]*\.deb' | sort -V | tail -1)
  curl -sL -o nce.deb "http://mirrors.ustc.edu.cn/debian/pool/main/f/fonts-noto-color-emoji/$DEB"
  mkdir nce_x && cd nce_x && ar x ../nce.deb && tar xf data.tar.*
  find . -name "*.ttf" -exec cp {} ~/.local/share/fonts/ \;
  fc-cache -f ~/.local/share/fonts
  # 验证：fc-list ":charset=1F465" family  应输出 Noto Color Emoji
  ```
  装完**必须重启程序**（Qt 启动时才扫描字体库）。
- **连带教训**：运行中的旧实例（`build/` 目录的旧二进制）在数据库被重建后连接已死、且内存里可能带密码锁定状态——排查登录问题时先 `ps -eo pid,lstart,cmd | grep QtSmartCabinet` 确认跑的是哪个二进制、何时启动的。

### 坑 9：摄像头“灯亮了”但人脸页黑圈无画面（帧回调没接上）
- **现象**：人脸识别页摄像头已打开（设备灯亮、日志 `Qt Multimedia camera started 640x480@30fps`），但前端预览是黑圈，`frameReady` 信号从未触发。
- **根因**：`CameraCapture::startQtMultimediaCapture()` 里直接 `m_captureSession->videoSink()` 取回调——但**从未调用过 `setVideoSink()`**，该函数此时返回 **nullptr**，帧回调 connect 根本没发生：摄像头启动了，却没有任何一帧被取到。与坑 2 同源：这条 Multimedia 分支是从未编译运行过的残缺代码。`frameReady` 只有 `onCaptureTimer` 里帧到位才发，`FaceCameraWidget` 靠它刷预览 → 永远黑。
- **修复（临时补丁，编后还原）**：
  ```cpp
  // startQtMultimediaCapture 中，替换原来的 videoSink() 直取：
  m_videoSink = new QVideoSink(this);
  m_captureSession->setVideoSink(m_videoSink);
  connect(m_videoSink, &QVideoSink::videoFrameChanged, this, [this](const QVideoFrame &frame) {
      QMutexLocker lock(&m_mutex);
      m_currentFrame = frame.toImage();
      m_frameReady = true;
  });
  // stopQtMultimediaCapture 中对应 delete m_videoSink；头文件加成员 QVideoSink* m_videoSink = nullptr;
  ```
- **验证方法**：帧回调里加低频日志（每 10 秒一条 `video frames flowing W x H`），offscreen 冒烟应看到实际帧尺寸（本机 video2 出 **1920x1080**，而非请求的 640x480，属设备默认格式，`toImage()` 会自动转换）。
- **教训**：“camera started” 日志只代表 `QCamera::start()` 成功，**不代表有帧**。验证摄像头链路必须看“帧级”证据。
