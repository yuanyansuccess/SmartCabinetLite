五、放错位置的数据存储与状态枚举设计

3.1 设计原则：货位状态机不放 misplaced

"一个位置一个工具"是系统铁律，由 tool_position_mapping 唯一键 (cabinet_id, layer, position) 物理保证。 错放是"一次识别事件"，不是货位的持续状态——货位状态机保持三值不变： pending（待入库）/ in_stock（在库）/ checked_out（已出库）。 若给货位加 misplaced 状态，"一个位置一个工具"的守恒就被打破（位置上既有主人又出现异物时状态无法自洽），且所有按状态过滤的查询（findAllInStockPositions 等 7 处）都要改，风险远大于收益。

3.2 错放数据的三层落点

落点本期做法理由
操作日志
sys_operation_log		每轮识别写一条 operation_type='checkin_round'/'checkout_round'，content 为 JSON：{round, order:[{toolCode,position,result}], misplaced:[{actualPosition,toolCode,expectedOwner}], unknown:[position], confidence}，result=success/fail表结构现成（type 是自由字符串、content 是 JSON text），零改表；满足"每轮留痕可追溯"
告警
sys_alert + sys_alert_type		本期不写（遵袁总前议"先提示"）。字典表已存在 mismatch（工具错放）/ rack_mismatch（货架错放）/ missing 三个现成类型将来要告警联动时直接启用，零建表零加类型
新表
tool_misplacement		不建单柜场景人工修正即可闭环；多柜场合作业队列是将来的独立需求，现在建属过度设计

3.3 本期新增状态枚举（全部走 SC:: 常量，禁裸字符串）

枚举取值用途
RecogItemResult（识别结果类型，页面/服务内存态，不入库）Matched / Empty / WrongTool / LowConfidence / UnknownItem / Misplaced比对函数 compareOrderWithRecognition 的逐项判定输出，驱动结果页红绿字
RoundState（单据轮次状态，内存态）Running / Passed / Partial / GivenUp重开柜闭环状态机，控制按钮可用性与上限
SC::ORDER_MAX_RETRY_ROUNDS3（红线常量，可调）重开柜整理轮次上限
SC::RECOG_MIN_CONFIDENCE0.85入库项"正确放入"的置信度门槛（低于判 LowConfidence）
SC::ORDER_ROUND_OP_CHECKIN / _CHECKOUT"checkin_round" / "checkout_round"轮次日志的 operation_type 值
