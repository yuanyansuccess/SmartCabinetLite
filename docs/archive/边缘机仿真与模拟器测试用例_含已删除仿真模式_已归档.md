# 边缘机仿真与模拟器测试用例

> 适用版本：SmartCabinetLite 2026-10-21 之后构建
> 目的：验证「工具出入库」流程在**仿真模式**与**模拟器联调**两套方式下，所有分支均可覆盖。

---

## 〇、先弄清通信角色（联调前提）

| 角色 | 在协议里的身份 | 说明 |
|------|----------------|------|
| 上位机（本程序） | TCP **服务端** | 正常启动即监听固定端口 `9000`，等边缘机连进来。端口写在程序内（`CommTypes.h`），界面和配置文件都不能改 |
| 边缘机 / 模拟器 | TCP **客户端** | 由它主动连上位机的 `9000` 端口 |

由此有两个直接结论：

1. **上位机侧没有任何"边缘机地址/端口"要填**。系统设置 → 网络配置 里的 IP 地址、子网掩码、默认网关、DNS 服务器都是**本机网卡参数**（真实部署时给柜机设固定 IP，方便边缘机找到本机）；"服务器地址"只在"组网管理"模式下启用。这些都与联调无关。
2. **连接地址填在模拟器里**，填的是上位机 IP（同机联调就是 `127.0.0.1`）。

两种方式**互斥**：开仿真模式时上位机不监听 9000，模拟器连不上；要与模拟器联调必须先关闭仿真。

---

## 一、配置方式（先选一种）

### 方式A：仿真模式（内置假边缘机，零外接）
1. 关闭正在运行的程序。
2. 用记事本打开程序目录下的 `system.ini`。
3. 找到或新增段落：
   ```
   [Edge]
   simulate=1
   ```
4. 保存并重新启动程序。
- 临时方式（不写文件）：启动时加参数 `--sim`。
- 关闭仿真：把 `simulate` 改为 `0` 或删除该行，重启。
- 程序里已无对应的界面勾选项，只能按上面的配置文件方式开启。

### 方式B：模拟器联调（EdgeSimulator.exe）
1. **关闭仿真模式**（按方式A的关闭方法改 `system.ini`），重启上位机；确认已退出仿真，否则上位机不监听 9000。
2. 上位机侧**不需要做任何配置**，保持正常运行即可（它在后台监听 9000）。
3. 模拟器侧：运行 `tools/EdgeSimulator/release/EdgeSimulator.exe`，在左上「连接上位机」区填**上位机 IP**——同机联调保持默认 `127.0.0.1`，端口保持默认 `9000`，点「连接」。
4. 状态变为「● 已连接 127.0.0.1:9000」即联调就绪（模拟器日志区会打印连接与收发帧过程）。
5. 协议按**单台边缘机**设计（回应帧靠"唯一在途请求"配对）：代码虽允许多个连接，但模拟器与真实边缘机同时接入会让回应配对错乱，联调前请先断开真实边缘机。

## 二、仿真模式测试用例（主成功路径，零依赖）

| 编号 | 用例 | 步骤 | 预期结果 |
|------|------|------|----------|
| TC-SIM-01 | 在线判定 | 配置 `simulate=1` 重启 → 进入工具出入库页 | 开箱前离线闸门放行（不提示"无法开箱"） |
| TC-SIM-02 | 开箱成功→开箱页 | 确认出入库单据 → 点确认 → 等待"开柜中" | 约 200ms 收到 open_ack 成功 → 弹出开箱页（取/放工具） |
| TC-SIM-03 | 识别返回空柜→不写库 | **用入库单**（工具 A 放到位置 P）→ 关柜点【我已关柜，开始核对 →】→ 等待"正在核对柜内工具" | 约 200ms 收到 recognize_ack 空清单 → 弹『出入库检查结果』：未完成 1 项、红字"货位为空，未检测到工具放入" → **不写库** |
| TC-SIM-04 | 取消开箱 | 确认出入库后，在"开柜中"弹窗点取消 | 提示"已取消"，零写库 |

> 说明：出入库页面已移除"边缘机链路状态"标签的**页面显示**，但底层在线判定、离线闸门、等待中掉线中止等安全逻辑仍生效。

## 三、模拟器测试用例（成功 / 失败 / 超时 / 写库 全分支）

> 前置：关闭仿真模式，模拟器与上位机已 TCP 联调（方式B）。

| 编号 | 用例 | 步骤 | 预期结果 |
|------|------|------|----------|
| TC-EDGE-01 | 开箱成功（默认） | 模拟器连接上位机 → 上位机确认出入库 → 开箱；模拟器默认收到 open_req 自动回 open_ack 成功 | 上位机弹出开箱页 |
| TC-EDGE-02 | 开箱失败（result=0） | ① 模拟器「识别回应 3.3」页签底部「开箱回应（3.7 开箱协议）」区点【开箱不回应（测开箱超时分支）】关闭自动成功；② 上位机触发开箱（模拟器记录 open_req 但不回应）；③ 点【开箱失败（result=0，测开箱失败分支）】 | 上位机提示"开箱失败"，不弹开箱页（覆盖开箱失败分支） |
| TC-EDGE-03 | 开箱超时 | 做完 TC-EDGE-02 第①②步后**不点失败**，等待约 9 秒（3 秒一次，首发+2 次重发用尽） | 弹『开箱失败』，内容含"开箱请求超时且重发次数用尽"；之后点【恢复开箱自动成功】复位 |
| TC-EDGE-04 | 识别正常场景 | 开箱 → 关柜核对；模拟器「识别回应 3.3」页签用场景按钮切换【正常清单】【有借有还】【无变化】 | 上位机按单据与识别清单比对，结果页红绿字与实际一致 |
| TC-EDGE-05 | 识别匹配→写库（入库落库） | 上位机做入库单（工具 A 放到位置 P）→ 关柜核对；模拟器「自定义帧」页签按真实字段发 recognize_ack（`position`=P、`tool_id`=工具编号 A、`confidence`≥0.85） | 比对通过 → **写库**（出入库记录落库）；仿真模式覆盖不到的分支在此测 |
| TC-EDGE-06 | 识别超时 | 模拟器点【识别不回应：关闭识别自动回应，测识别超时重发（第5章）】→ 上位机关柜核对 → 等约 9 秒 | 弹『核对失败』，内容含"识别请求超时且重发次数用尽"，并询问"是否重新核对？（不用重新开箱）" |
| TC-EDGE-07 | 链路掉线 | 上位机开箱等待中，模拟器断开 TCP（点「断开」或关闭模拟器） | 弹『链路中断』"开箱已终止"（覆盖等待中掉线分支） |
| TC-EDGE-08 | 用户取消开箱 | 开柜中等候中点取消 | 提示"已取消"，零写库 |
| TC-EDGE-09 | 8 路摄像头全正常→开箱成功 | 周期帧 Tab 8 路摄像头保持默认 `ok` → 上位机确认出入库→开箱 | 模拟器回 `open_ack` 成功 → 弹出开箱页（验证 8 路全 ok 不拦截） |
| TC-EDGE-10 | 摄像头异常→上位机禁止开箱 | 周期帧 Tab 把 **CAM3** 设为 `offline`（任意一路非 `ok` 即可）→ 上位机确认出入库→开箱 | 上位机提示"以下摄像头状态异常，禁止开柜：CAM3(offline)"，**不弹开箱页、不写库**（覆盖上位机摄像头闸门） |
| TC-EDGE-11 | 摄像头异常→模拟器联动拒绝 | 同上把 CAM3 设为 `offline` 后，直接用「自定义帧」页签构造 `open_req` 发给模拟器（越过上位机闸门以验证边缘侧） | 模拟器回 `open_ack` `result=0`，`message` 含"以下摄像头状态异常，禁止开柜：CAM3(offline)"（验证模拟器与真实边缘机一致的拒绝行为） |

> 摄像头状态含义（8 路，CAM1..CAM8）：`ok`=正常 / `offline`=掉线 / `low_light`=光照不足 / `dirty`=镜头脏污 / `comm_error`=通信异常 / `(空-不报自检)`=该路不出现在 `camera_status`（全部选空则数组为空，上位机按"自检缺席"不拦截）。**安全策略：周期帧上报的 8 路摄像头任一状态非 `ok`，上位机与模拟器两端都拒绝开柜。**

> **TC-EDGE-05 自定义帧示例**（字段与程序解析一一对应）：
> ```json
> {"type":"recognize_ack","success":true,"request_id":"<复制的req编号>",
>  "items":[{"position":"A-01-02","tool_id":"T0001","class_id":"socket","confidence":0.92}]}
> ```
> 两个关键点，填错会被直接丢弃或判不通过：
>
> ① **`request_id` 必须是字符串，且与上位机本次请求完全一致**（形如 `req-1761123456789-7`）。填数字 `1` 会被当成空串，按协议 3.6-② 直接丢弃并计数。编号可从模拟器日志的 `RX` 行或上位机日志复制。
>
> ② **物品字段是 `position` / `tool_id` / `class_id` / `confidence`**（`alert_type`、`alert_level` 可选），**没有 `tool_code`，也没有 `status`**。
> 判定规则：入库项看"该货位识别出的 `tool_id` 是否等于单据上的工具编号，且 `confidence ≥ 0.85`"；出库项看"该货位是否已识别不到工具"。

## 四、分支覆盖总表（对应"每个分支都能覆盖到"）

| 出入库分支 | 仿真模式 | 模拟器 | 覆盖用例 |
|------------|----------|--------|----------|
| 单据空 / 同工具重复 / 校验失败 | ✅ 均可 | ✅ | 手动 |
| 离线闸门（提示无法开箱） | ❌（仿真永远在线） | ✅（关仿真且不启动模拟器） | 关仿真+不连 |
| 发开箱指令 | ✅ | ✅ | TC-SIM-02 / TC-EDGE-01 |
| 开箱成功→弹开箱页 | ✅ | ✅ | TC-SIM-02 / TC-EDGE-01 |
| 开箱失败（result=0） | ❌（仿真永远成功） | ✅ | TC-EDGE-02 |
| 开箱超时 / 补发放弃 | ❌ | ✅ | TC-EDGE-03 |
| 开柜中用户取消 | ✅ | ✅ | TC-SIM-04 / TC-EDGE-08 |
| 开柜中链路掉线中止 | ❌（仿真不连 socket） | ✅ | TC-EDGE-07 |
| 摄像头异常禁止开箱（任一非 ok） | ❌（仿真周期帧 8 路全 ok） | ✅ | TC-EDGE-10（上位机闸门）/ TC-EDGE-11（模拟器拒绝） |
| 识别返回空柜→不写库 | ✅ | ✅ | TC-SIM-03 / TC-EDGE-04（选【无变化】） |
| 识别匹配→写库（落库） | ❌（仿真返回空清单） | ✅ | TC-EDGE-05 |
| 识别超时 | ❌ | ✅ | TC-EDGE-06 |

**结论**：仿真模式覆盖"主成功路径 + 空柜不写库 + 取消"；开箱失败 / 超时 / 掉线 / 写库这几个内置假边缘机天然覆盖不到的分支，由「上位机 + 模拟器」覆盖。两套合起来 = 全部分支覆盖。
