二、各步骤界面元素清单

步骤界面元素作用与取值
① 连接与数据 上位机地址 / 端口默认 127.0.0.1:9000，取 ini，可改
连接 / 断开 按钮连上上位机；断开后按退避策略自动重连（1/2/4/8/16/30 秒）
数据库：主机/端口/库名/账号/口令全部读 ini，不让测试人员手输；界面上只显示"已连接 smart_cabinet"，可点【改连接参数】临时改
【从库读取工具与货位】读 tool_info / tool_position_mapping / tool_cabinet（与上位机同一批表、同一库），填货位与工具下拉框
【一键标准联调】连接 + 读库 + 生成全量在库基线清单 + 识别回应=自定义清单 + 周期帧自动发送，一步到位
收发计数收 / 发 / 坏帧 / 丢弃帧计数，排查丢帧时一眼定位
② 单据模拟 清单表（主控件）见第三节列定义；一行 = 一个货位的识别结果
【按本单生成清单】在清单区先勾选"本单工具"（从库里选），点此按钮自动生成：本单-入库行 + 本单-出库行 + 非本单在库行（边缘机"全部扫描"基线）
【全部识别正常】一键把全表识别结果改回 normal（造"完美通过"场景）
【只保留本单行】只回应本单相关货位，模拟"边缘机只扫了本单区域"
【插入行】/【删除选中行】手工补一行（货位+编号+归属+结果）或删掉误加的行
③ 识别回应
页顶版本/开箱，下面识别回应		 版本查询 3.5版本号（默认 1.2.0）+【立即回 version_ack】；上位机发 version_query 时自动回
开箱回应 3.7自动成功 / 固定失败（可填原因文案）/ 不回应
回应内容 3.3下拉：自定义清单 / 正常清单 / 有借有还 / 无变化 / 错放 / 未知物 / 置信度不足 / 缺失 / 不回应
回应延迟 ms0 = 立即；>3000 可触发上位机超时重发（异常 #7）
多轮序列按序回放：第1轮全过 → 第2轮部分未过 → 第3轮仍不过（异常 #19）

帧级异常坏帧 JSON / 未知 type / 超长帧 / 乱序 request_id / 重复回包 ×2 / 粘包（异常 #9）
立即动作【立即发一帧周期帧】等调试按钮
⑤ 场景预设 场景预设下拉 6 项：正向全过 / 部分未过 / 三轮兜底 / 离线拒绝 / 逆向借出转出库 / 摄像头闸门；套用后清单、回应场景、多轮序列、摄像头状态同步改好，可再手动微调

生成规则（一条规则对应一个业务场景）

按钮 / 操作生成结果典型用途
【按本单生成清单】（本单 = 入库工具集 ∪ 出库工具集）本单-入库行：本单目标货位 + 正确工具 + 正常
本单-出库行：本单原货位 + 该工具 + 正常（上位机判"已取走"靠本单出库行缺失，见下）
非本单行：库内其余在库货位（模拟边缘机扫全柜）		正向入库 / 正向出库 / 逆向借出转出库 三种单据一次配齐
【全部改正常】非出库行统一 alert_type=none、级别 0、置信度 0.95（出库行保持"货位空"，那是已取走的意思）造"全部通过、整单写库"
【只保留本单行】背景行取消勾选回应（行仍留在表里，方便看清排除了哪些货位）边缘机只覆盖本单区域
选中一行改"识别结果=错放"该行 alert_type=misplaced，且可指定"实际在哪个货位"异常 #13 错放
选中一行改"未知物品"tool_id 留空、alert_type=unknown异常 #14 未知物品
选中一行改"缺失"该货位不出现，alert_type=missing 记在别处异常 #15 在库工具缺失
选中一行改"低置信"置信度 < 85异常 #12 部分未过
【清空清单】清单为空异常 #10 识别清单为空（整单判未检测到）
出库语义提醒：上位机判"出库这行通过"= 该货位在识别实况里不再出现该工具（工具已被取出）。因此出库场景的正确做法是：清单里保留该货位行但把工具编号置空（= 货位已空），或直接不勾该行；同时【按本单生成清单】会自动把出库行置为"货位空"。
候选列表排序：②页三个候选列表（待入库 / 在库 / 借出中）一律按货位顺序排列（柜号-层号-位号），从上往下扫一眼就知道柜里摆了什么；已实测生效。

四、与出入库流程图的异常覆盖矩阵（25 项逐项落到界面控件）

#异常场景界面操作位置说明
1行未选工具上位机侧（模拟器不造）单据校验在上位机，模拟器无法也不必造
2空单据上位机侧同上
3同工具多行入库上位机侧同上
4位置被占 / 工具加载失败上位机侧同上
4-1借出工具已归还或再次出库②【按本单生成清单】· 归属选"本单-借出转出库"清单里把该工具去掉即可复现
4-2借出工具与在库工具混在同一单②清单同时存在两种归属行上位机仍走开箱，借出行不参与核对
5边缘机链路离线①【断开】／④ 停发周期帧 15s两种方式：真断链 / 只停心跳
6关柜信号超时③ 开箱回应=不回应上位机等不到关柜信号
7识别请求超时③ 回应内容=不回应 ／ 延迟 >3000ms测上位机重发
8在途请求期间链路中断① 识别发出后立即【断开】恢复后按原 request_id 补发
9坏帧 / 半帧 / 超长④ 坏帧 JSON ／ 未知 type ／ 超长帧链路层丢弃并计数
10识别清单为空②【清空清单】整单判"未检测到"，进整理闭环
11全部通过②【按本单生成】+【全部识别正常】正向主路径
12部分未过② 把某一行改"低置信"或"货位空"结果页红字 + 双出口
13错放 misplaced② 行改"错放"结果页提示行，不自动挪动
14未知物品 unknown② 行改"未知物品"该货位若属本单则该行失败
15在库工具缺失 missing② 把非本单行删掉仅提示不拦本单
16等待态点取消上位机侧用户操作
17开柜不操作直接关柜② 出库行置"货位空"目标位全空 → 全失败 → 第 1 轮整理
18整理中途又开柜（反悔）③ 开箱回应=自动成功，再手动【立即发一帧周期帧】上位机放弃本轮识别
193 轮仍不全过③ 多轮序列：①正常 → ②部分未过 → ③仍不过第 3 轮按实况写库兜底
20页面关闭时有在途请求上位机侧实现层防护
21DB 断连 / 事务失败① 数据库参数改成不可达地址系统错 → 提示写入失败可重试
22部分写成功机制保证上位机单事务，不会发生
23结果页开着时他人开柜上位机侧不影响本次
24关闭结果页后改单据再确认上位机侧自然重走全流程
25摄像头自检异常④ 周期帧里把某路 CAM 设为 dirty / offline两端一致：拒绝开柜，零写库
覆盖结论：25 项中 13 项由模拟器界面直接造（4-1/4-2/5/6/7/8/9/10/12/13/14/15/17/19/21/25），其余 12 项属上位机内部校验或用户操作，模拟器不重复造。上表同时作为《测试规程》第 5 章"场景预配置清单"的界面依据。

六、袁总拍板结论与落地结果

#事项袁总结论落地情况

6场景预设清单全部落地已落地：6 个预设（正向全过 / 部分未过 / 三轮兜底 / 离线拒绝 / 逆向借出转出库 / 摄像头闸门）
